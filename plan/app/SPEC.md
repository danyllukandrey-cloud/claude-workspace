## Goals — що має вміти перша версія

**Одна generic картка**, з якою працює агент, доведена до стану, коли нею можна користуватись.
«Generic» означає: код один, тема картки — це просто дані, які вводить користувач.

1. **Створити картку.** Назва (для показу) + «Опис» — коротка декларація навіщо ведеться цей
   напрямок. Картка з'являється блоком на дошці (базовий алгоритм розкладки — зліва знизу,
   заповнення рядка, новий рядок вище).
2. **Додати блок-метрику.** Довільна кількість блоків на картку, без жорсткого ліміту.
   Кожен блок: **кількість** (довільна одиниця — штуки, кілометри, літри…), **частота**
   (опційно, для звірки факту з планом), **ціль у часі** (дата досягнення або позначка
   «постійний процес»).
3. **Записати прогрес через чат з агентом.** Вільний текст («прочитав книгу») → агент
   перепитує підтвердження, до якого блоку записати → лічильник оновлюється. Ручне редагування
   лічильника теж можливе, без чату.
4. **Побачити Відстеження.** Тільки пораховані числа/прогрес на звороті картки — без текстової
   інтерпретації на самій картці (аналітика — окремий екран, п.6).
5. **Побудувати структуру (Карту).** Групування карток — три варіанти (одна картка / вільно
   без групування / за логікою: центр-пріоритет, зліва-центр-справа тощо), завжди редаговане
   користувачем перетягуванням.
6. **Побачити аналітику.** Окремий екран Структури — зведені дані з усіх карток, прогрес,
   висновок щодо ефективності. Вкладки нижньої навігації: загальна схема → картки → аналітика
   → … → налаштування (завжди останні).
7. **Синхронізація між пристроями.** Увійшов на іншому пристрої через Google — дані на місці.
8. **Дані переживають перезавантаження й офлайн.** `localStorage` — локальний кеш (~2 МБ),
   бекенд — джерело правди для синхронізації.
9. **Помилки видно на самій картці, агент пояснює** — не системне вікно, не мовчазний збій.
10. **Записувати історію змін Структури.** Заведення, перейменування, об'єднання й закриття
    напрямків фіксуються **з першого дня** як події з часовою міткою. Показ літопису — не
    в цій версії ([D-39](../../docs/DECISIONS.md)); запис зараз нічого не коштує, а додати
    його заднім числом неможливо — минулого вже не буде.

**Чому саме це.** Дев'ять блоків інтерв'ю встановили: агент — не окрема функція «на потім», а
спосіб, яким картка взагалі наповнюється (D-31 — агент технічний виконавець, відповідає на
запит, не ініціює сам). Без чату й бекенда генерик-модель не працює так, як спроєктована.

## Non-goals — чого в першій версії не буде

> Список **відкритий**: сюди дописуємо, щойно з'ясовується, що чогось свідомо не робимо.

| Не робимо | Наслідок для користувача | Звідки рішення |
|---|---|---|
| **SMS / телефон-вхід** | вхід лише через Google | [DECISIONS D-33](../../docs/DECISIONS.md) — додається пізніше |
| **Готові інтеграції конекторів** (Google Fit, Goodreads тощо) | конфлікт-логіка й місце під конектор готові, самі інтеграції підключаються по одній пізніше | [design-review §Блок 0, 6](../features/life-area-card/design-review.md) |
| **Максимальна кількість карток/метрик — без визначеного числа** | агент попереджає про «перебір», але жорсткого ліміту UI поки нема | окреме дослідження, не проведене |
| **Мануал і концепція як писані документи** | агент і користувач поки без цих матеріалів | [DECISIONS Q-7](../../docs/DECISIONS.md) |
| **Концепція ефективності метрик і пороги** | аналітика показує дані, але без формалізованих порогів «ефективно/неефективно» | [DECISIONS Q-6](../../docs/DECISIONS.md) |
| **Публікації в магазинах застосунків** | відкривається як сайт; PWA дозволяє «встановити» іконку | [ADR-0001](../../docs/adr/0001-frontend-stack.md) |
| **Офіційне партнерство з Anthropic** | ПЛАН перепродає використання Claude API з націнкою, без спецугоди | [DECISIONS D-32](../../docs/DECISIONS.md) — записана амбіція, не MVP |
| **Показ літопису змін Структури** | історія пишеться з першого дня (Goals п.10), але окремого екрана з нею немає | [DECISIONS D-39](../../docs/DECISIONS.md) — показуємо, коли буде що показувати |

## Acceptance criteria — коли вважаємо, що вдалось

**Головний критерій — життєвий.** Андрій веде в цій картці реальний напрямок свого життя і не
повертається до нотаток чи таблиці. Якщо повертається — щось не так, і причина важливіша за
будь-який тест.

Перевіряємі ознаки:

- [ ] Картку можна створити з довільною назвою й Описом — без жорстко зашитої теми
- [ ] До картки можна додати довільну кількість блоків-метрик, кожен з кількістю, опційною
      частотою і ціллю в часі (дата або «постійний процес»)
- [ ] Вільний текст у чат («прочитав книгу») агент розпізнає, перепитує підтвердження,
      записує в правильний блок після «так»
- [ ] Відстеження на звороті картки показує лише числа, без тексту
- [ ] Структуру (Карту) можна побудувати одним із трьох варіантів і перетягуванням змінити
- [ ] Екран аналітики показує зведені дані з усіх карток
- [ ] Вхід через Google працює; дані видно на другому пристрої після входу
- [ ] Після перезавантаження сторінки й офлайн дані на місці (кеш ~2 МБ не перевищено)
- [ ] Некоректне введення дає зрозуміле пояснення від агента на картці, не порожній екран
- [ ] `npm run build` проходить без помилок; `npm test` зелений
- [ ] Жоден файл у `domain/` не імпортує React, `localStorage` чи мережевий виклик напряму
