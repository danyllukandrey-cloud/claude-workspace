# CLAUDE.md — конвенції коду застосунку «ПЛАН»

> Цей файл діє для всього, що лежить у `plan/app/`. Правила спілкування з Андрієм — у
> кореневому `CLAUDE.md` репозиторію; тут тільки технічні конвенції коду.

## Правило залежностей (найважливіше)

Стрілка означає «має право імпортувати».

```
ui       →  domain                   вигляд знає правила
domain   →  НІЧОГО                   ні React, ні localStorage, ні Tailwind
domain   →  shared/storage/port.ts   виняток: тільки інтерфейс, ніколи не local.ts
app      →  cards, shared            app склеює: підставляє local.ts у port.ts
картка   →  картка                   ЗАБОРОНЕНО. Тільки через shared/ або app/
```

**Чому це записано словами.** TypeScript не вміє перевіряти таке правило сам — на відміну від
Go, де пакети під `internal/` фізично неможливо імпортувати ззовні. Тут правило існує лише
настільки, наскільки воно написане. Не написане = порушене ненавмисно.

Обґрунтування вибору — [ADR-0004](../../docs/adr/0004-scaffold-architecture.md).

## Структура

```
src/
  cards/<slug>/
    domain/      чисті правила картки
    ui/          React-компоненти картки
    index.ts     публічний вхід: що видно назовні
  shared/
    ui/          спільні примітиви: CardShell, Button, NumberField
    storage/
      port.ts    інтерфейс сховища
      local.ts   реалізація через localStorage
    priority/    резерв, у MVP не будуємо
  app/           точка входу, реєстрація карток, підстановка реалізацій
```

## Конвенції

- **Нова картка** = нова папка `src/cards/<slug>/` з `domain/`, `ui/`, `index.ts`,
  зареєстрована в `src/app/main.tsx`. Наявні картки при цьому не чіпаються.
- **Імпорт картки ззовні** — тільки через її `index.ts`. Лізти напряму в `domain/` або `ui/`
  чужої картки не можна.
- **Зберігання даних** — тільки через `shared/storage/`. Жодна картка не звертається до
  `localStorage` напряму ([ADR-0003](../../docs/adr/0003-client-only-persistence.md)).
- **ID записів** — `crypto.randomUUID()`.
- **Версія формату даних** — ключ `schemaVersion` у сховищі, щоб потім мігрувати старі дані.
- **Помилки** — валідація всередині картки, повідомлення показується на самій картці.
  Ніяких `alert()` і `confirm()` — вони блокують інтерфейс.
- **Тести** — `*.test.ts(x)` поруч із файлом. Логіку з `domain/` тестуємо окремо від UI:
  це чисті функції, браузер їм не потрібен.
- **Стилізація** — Tailwind CSS, спільні примітиви з `shared/ui/`.

## Команди

Справжні команди живуть **тільки** в `package.json` → `scripts`:

```
npm install      поставити залежності (один раз)
npm run dev      запустити локально
npm test         тести
npm run lint     перевірка типів (ESLint додамо разом з CI — задача S5)
npm run build    зібрати для публікації
```

**`Makefile` — не дубль.** У ньому лише переадресація (`test: npm test`), щоб на macOS та
Linux працювала звична команда `make test`. Список команд існує в одному місці. Тривогу за
правилом єдиного джерела піднімати не треба.

На Windows `make` відсутній — Андрій запускає `npm run ...`.

## Стек

React 18 + TypeScript + Vite + PWA + Tailwind CSS. Тести — Vitest + React Testing Library.
Обґрунтування — [ADR-0001](../../docs/adr/0001-frontend-stack.md).

## Чого тут немає і не має бути

- **Бекенду.** Дані живуть у браузері ([ADR-0003](../../docs/adr/0003-client-only-persistence.md)).
- **Бібліотеки керування станом.** React `useState` / `useContext` достатньо, поки карток мало.
- **React Query.** Немає мережевих запитів — немає чого кешувати.
- **Автоматичної перевірки правила залежностей.** Якщо порушення почнуть траплятись —
  тоді ESLint `no-restricted-imports`. Поки що інструмент без потреби.
