# CLAUDE.md — конвенції коду застосунку «ПЛАН»

> Цей файл діє для всього, що лежить у `plan/app/`. Правила спілкування з Андрієм — у кореневому `CLAUDE.md` репозиторію; тут тільки технічні конвенції коду.

## Правило залежностей (найважливіше)

Стрілка означає «має право імпортувати».

```
ui       →  domain                   вигляд знає правила
domain   →  НІЧОГО                   ні React, ні localStorage, ні Tailwind
domain   →  shared/storage/port.ts   виняток: тільки інтерфейс, ніколи не local.ts
app      →  cards, shared            app склеює: підставляє local.ts у port.ts
картка   →  картка                   ЗАБОРОНЕНО. Тільки через shared/ або app/
```

**Чому це записано словами.** TypeScript не вміє перевіряти таке правило сам — на відміну від Go, де пакети під `internal/` фізично неможливо імпортувати ззовні. Тут правило існує лише настільки, наскільки воно написане. Не написане = порушене ненавмисно.

Обґрунтування вибору — [ADR-0004](../../docs/adr/0004-scaffold-architecture.md).

## Конвенції

> ⚠️ **Оновлено 2026-08-16 (D-23).** Картка стала generic/universal типом. Нижче — де раніше було «нова картка = нова папка», тепер розведено: нова папка коду потрібна лише раз (сам механізм), нова картка користувача — це новий запис даних.

- **`src/cards/life-area-card/`** — один код назавжди, з `domain/`, `ui/`, `index.ts`, зареєстрований у `src/app/main.tsx`. Нову папку в `src/cards/` заводимо тільки якщо з'явиться картка з **принципово іншою** логікою (не просто інші дані) — виняток, не норма.
- **Нова картка користувача** (Навчання, Здоров'я, Кар'єра…) = новий запис даних усередині `life-area-card`, без нового коду. Наявні картки-записи при цьому не чіпаються.
- **Новий тип блоку-метрики** (не лише «кількість + ціль», наприклад нотатка без прогресу) = розширення бібліотеки типів усередині `life-area-card/domain/`, без переписування коду вже існуючих карток-записів.
- **Імпорт картки ззовні** — тільки через її `index.ts`. Лізти напряму в `domain/` або `ui/` чужої картки не можна.
- **Зберігання даних** — тільки через `shared/storage/`. Жодна картка не звертається до `localStorage` напряму ([ADR-0003](../../docs/adr/0003-client-only-persistence.md)).
- **ID записів** — `crypto.randomUUID()`.
- **Версія формату даних** — ключ `schemaVersion` у сховищі, щоб потім мігрувати старі дані.
- **Помилки** — валідація всередині картки, повідомлення показується на самій картці. Ніяких `alert()` і `confirm()` — вони блокують інтерфейс.
- **Тести** — `*.test.ts(x)` поруч із файлом. Логіку з `domain/` тестуємо окремо від UI: це чисті функції, браузер їм не потрібен.
- **Стилізація** — Tailwind CSS, спільні примітиви з `shared/ui/`.

## Команди

Справжні команди живуть **тільки** в `package.json` → `scripts`:

```
npm install      поставити залежності (один раз)
npm run dev      запустити локально
npm test         тести
npm run lint     перевірка типів (ESLint додамо разом з CI — задача S5)
npm run build    зібрати для публікації
```

**`Makefile` — не дубль.** У ньому лише переадресація (`test: npm test`), щоб на macOS та Linux працювала звична команда `make test`. Список команд існує в одному місці. Тривогу за правилом єдиного джерела піднімати не треба.

На Windows `make` відсутній — Андрій запускає `npm run ...`.

## Чого тут немає і не має бути

- **Бекенду для зберігання карток даних як такого.** Дані картки й далі насамперед клієнтські ([ADR-0003](../../docs/adr/0003-client-only-persistence.md)) — `localStorage` як кеш. Але мінімальний бекенд **уже є** для іншого: агент (Claude API), синхронізація, вхід ([D-24](../../docs/DECISIONS.md)). Не плутати — це не «немає бекенду взагалі».
- **Бібліотеки керування станом.** React `useState` / `useContext` достатньо, поки карток мало.
- **React Query — поки не вирішено.** Мережеві запити тепер реальні (бекенд, D-24), рішення додавати React Query чи ні ще не ухвалене.
- **Автоматичної перевірки правила залежностей.** Якщо порушення почнуть траплятись — тоді ESLint `no-restricted-imports`. Поки що інструмент без потреби.
