# .githooks — перевірки, що спрацьовують під час коміту

## Що тут лежить

| Файл | Коли спрацьовує | Що робить |
|---|---|---|
| `commit-msg` | під час кожного `git commit` | не пропускає коміт без мітки `Decision:` |
| `post-merge` | після `git pull` | друкує підказку запустити `/session-brief` — нічого не блокує |
| `pre-push` | перед `git push` | питає `[y/N]`, чи запустити `/pm-end` — на "так" **зупиняє push** (exit 1) |

`post-merge` — чисте нагадування, завжди завершується успішно. `pre-push` —
інтерактивний: питає в терміналі (через `/dev/tty`, бо звичайний stdin хука зайнятий
даними Git про push) і на "так" зупиняє push, щоб ти встиг зайти в Claude Code,
ввести `/pm-end` і запушити повторно. Немає термінала (CI, GUI-клієнт без консолі) —
питати нема як, push іде без зупинки. (У Git немає хука "після push" — `pre-push`
спрацьовує до відправки, це найближчий робочий еквівалент.)

## Чому папка тут, а не в `.git/hooks/`

Стандартна папка `.git/hooks/` лежить **поза репозиторієм** і через `git push`/`git pull`
не передається. На другому комп'ютері хука просто не було б — і ти б цього не помітив.

Тому файли лежать тут (звичайна тека проєкту, потрапляє в git), а Git отримує на них
вказівник однією командою. **На кожній машині її треба виконати один раз:**

```bash
git config core.hooksPath .githooks
```

Перевірити, що ввімкнено:

```bash
git config core.hooksPath
```

Має вивести `.githooks`. Якщо порожньо — хуки не працюють, виконай команду вище.

## Де правило, а не його копія

Що саме писати в мітці, які є варіанти й навіщо це все — **[`CLAUDE.md` § Рішення і
зміни](../CLAUDE.md)**. Тут цього тексту навмисно немає: скопіювати правило означало б
завести другу копію, яка з часом розійдеться з першою (див. «правило єдиного джерела»).

Найчастіше правило й шукати не доведеться — хук друкує повну інструкцію просто в тексті
помилки, у ту саму секунду, коли вона потрібна.

## Якщо треба обійти

```bash
git commit --no-verify
```

Це поручні від забудькуватості, а не замок. Але якщо тягнешся до `--no-verify` частіше
ніж раз на місяць — проблема не в хуку, а в правилі; тоді його треба переглядати.
