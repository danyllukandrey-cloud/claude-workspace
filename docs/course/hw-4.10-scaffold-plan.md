## 0. Словник (щоб далі читалось без спотикань)

| Термін | Простими словами |
|---|---|
| **Scaffold** | «риштування», початковий каркас проєкту: структура папок + базові файли. Ще без робочого коду |
| **Bounded Context (BC)** | самостійна частина системи зі своєю зоною відповідальності й чіткою межею. Наприклад «картки» окремо, «сховище» окремо |
| **Clean Architecture** | спосіб розкладати код так, щоб головна логіка (правила продукту) не залежала ні від React, ні від сховища даних. Це правило **напрямку залежностей**, а не назви папок |
| **Dependency rule** | правило залежностей: хто кого має право «знати» |
| **Port (порт)** | інтерфейс — опис «що мені потрібно», без опису «як це зроблено». Картка каже «мені треба зберегти дані», а хто саме зберігає — не її справа |
| **ADR** | Architecture Decision Record — запис одного архітектурного рішення: що вирішили і чому |
| **SPEC** | документ «що будуємо і що НЕ будуємо», записаний до першого рядка коду |
| **Makefile** | файл із короткими ярликами до довгих команд: пишеш `make test`, воно виконує те, що записано під `test:` |
| **npm scripts** | те саме, але у світі JavaScript: розділ `scripts` у `package.json`, команда `npm run dev` |
| **Initial commit** | перший збережений знімок каркасу в історії Git |

## 3. Суперечності, знайдені в репозиторії, і як вони зняті

Кожна перевірена по файлах, не по пам'яті.

### 3.1 ADR-0002 і Clean Architecture — знято рішенням R-1

**Що знайшли.** [ADR 0002](../adr/0002-card-module-architecture.md) у розділі «Розглянуті
варіанти» **явно розглянув і відхилив** пункт 2: «групування за технічним типом (всі компоненти
в `components/`, вся логіка в `logic/`) — класичний layered підхід». Верхньорівневі папки
`domain/ application/ infrastructure/ presentation/` — це буквально він.

**Чому це не глухий кут.** Clean Architecture — правило напрямку залежностей, а не назви тек.
Урок каже прямо: «Clean Architecture гнучка — структуруй під свій проєкт». Усталена практика
фронтенду — папка на фічу як база, шари **всередині** фічі.

**Рішення.** Шари всередині картки. ADR-0002 лишається **чинним**; ADR-0004 його **уточнює**,
а не скасовує.

### 3.2 `make` на Windows не працює — знято рішенням R-4

**Що знайшли.** `verify.ps1`, рядок 2, дослівно: «Windows equivalent of `make verify` from the
course starter (**no make on Windows**)». Тобто Makefile у цьому репозиторії вже одного разу
виявився марним, і під нього писали заміну на PowerShell.

**Рішення.** Справжні команди живуть у `package.json` → `scripts`. `Makefile` створюємо, але в
ньому лише переадресація: `test: npm test`. Андрій запускає `npm run dev`, куратор на Mac або
контейнер на Linux запускає `make test` — обидва шляхи ведуть в один і той самий рядок.

> **Примітка для майбутніх сесій.** `Makefile` з переадресаціями — **не дубль**. Список команд
> існує в одному місці (`package.json`); Makefile лише перекидає виклик. Тривогу за правилом
> єдиного джерела піднімати не треба. Цей абзац дублюється рядком у `plan/app/CLAUDE.md`.

### 3.3 Нумерація ADR — знято рішенням R-2

**Що знайшли.** У `docs/adr/` вже є `0001-frontend-stack`, `0002-card-module-architecture`,
`0003-client-only-persistence`. Завдання просить створити `0001-initial-setup.md`.

**Рішення.** Новий ADR іде під номером **0004**. У здачі — один рядок пояснення.

### 3.4 Неоголошений переїзд `features/` — знято рішенням R-3

### 3.5 Мертві правила в `.claude/settings.json` — прибрати

В `allow` висять `Bash(make verify*)`, `Bash(make test)`, `Bash(make build)`, `Bash(make clean)` —
дозволи на команди, яких на машині немає. Спадок курсового стартера. Шкоди немає, але це сміття.

Корисна знахідка поруч: `npm run *`, `npm test`, `npx vite/vitest/tsc/eslint/prettier` **уже
дозволені**. Шлях через npm-скрипти працює без жодних змін у налаштуваннях.

## 4. Структура папок і правило залежностей

Це і є «матеріалізація BC у файлову систему» — головна ідея уроку.

```
plan/app/src/
  cards/<slug>/
    domain/      чисті правила картки — без React, без localStorage, без Tailwind
    ui/          React-компоненти картки
    index.ts     публічний вхід: що з картки видно назовні
  shared/
    ui/          спільні примітиви: CardShell, Button, NumberField
    storage/
      port.ts    інтерфейс сховища — ЩО картці потрібно
      local.ts   реалізація через localStorage — ЯК це зроблено
    priority/    заготовка на майбутнє, у MVP не будуємо
  app/           точка входу, реєстрація карток, підстановка реалізацій у порти
```

**Dependency rule — піде в `plan/app/CLAUDE.md` дослівно:**

```
ui       →  domain                  вигляд знає правила
domain   →  НІЧОГО                  ні React, ні localStorage, ні Tailwind
domain   →  shared/storage/port.ts   дозволено: тільки інтерфейс, ніколи не local.ts
app      →  cards, shared            app склеює: підставляє local.ts у port.ts
картка   →  картка                   ЗАБОРОНЕНО. Тільки через shared/ або app/
```

TypeScript не вміє це перевіряти сам (на відміну від Go), тому правило має бути **написане
словами** — інакше Claude порушить його ненавмисно. Урок підкреслює це окремо.

**Як межі з `architecture-map.md` лягають у цю структуру:**

| Межа з architecture-map | Куди лягає |
|---|---|
| `app-shell` | `plan/app/src/app/` |
| `card:portfolio-rebalancing-card` | `plan/app/src/cards/portfolio-rebalancing-card/` (цілісно, з `domain/` і `ui/` всередині) |
| `shared/ui` | `plan/app/src/shared/ui/` |
| `shared/storage` | `plan/app/src/shared/storage/port.ts` + `local.ts` |
| `shared/priority` | `plan/app/src/shared/priority/` — порожня заготовка |

### Картка Блоку 1 · Прибирання документації + оголошення переїзду

**Статус:** чекає на «+»

#### Мета

Привести документи в стан, де жодне посилання не веде в нікуди і жоден документ не бреше про
те, де що лежить. Каркас має лягти на впорядковану базу.

#### Що робимо

**1. `git pull`** — робота йде з двох ПК, редагуємо 5 файлів, які могли змінитись.

**2. Полагодити 8 битих посилань** (перевірено пошуком по репозиторію, не на око):
