# ADR-0001: Стек фронтенду — React + TypeScript + Vite, як PWA

- Статус: Accepted (прийнято за замовчуванням, бо користувач не встиг підтвердити — переглянь і скажи, якщо треба інше)
- Дата: 2026-07-02

## Контекст

Потрібен застосунок "ПЛАН", який людина відкриває з телефону як звичайний застосунок (іконка на
екрані), а всередині — картки, що вводять дані та "перевертаються" показуючи розрахунок. Проєкту
доведеться рости: спочатку одна картка (ребалансування портфелю), потім багато (фінанси, здоров'я,
кар'єра).

## Розглянуті варіанти

1. **React + TypeScript + Vite, зібраний як PWA** — сайт, що встановлюється на головний екран.
2. **Простий HTML/CSS/JavaScript без фреймворку** — найпростіше технічно, але дублювання коду
   картки під час росту кількості карток.
3. **React Native (нативний застосунок)** — "рідне" відчуття мобільного застосунку, але важкий
   інструментарій для новачка (Xcode/Android Studio) та публікація в стори.

## Рішення

Обрано варіант 1: **React + TypeScript + Vite**, зібраний і налаштований як PWA.

## Обґрунтування

- React дає компонентну модель "одна картка = один компонент" — природно лягає на "багато карток"
  з майбутнього бачення проєкту.
- TypeScript ловить помилки типів (наприклад, переплутане число з текстом) під час написання коду,
  а не під час використання застосунку.
- Vite — швидкий дуже сервер розробки і збирання, стандарт для нових React-проєктів.
- PWA дає "встановлення як застосунок" без публікації в App Store/Google Play (довше й платно),
  одним кодом для телефону й комп'ютера.

## Наслідки

- Потрібне початкове налаштування PWA (manifest-файл + service worker — фоновий скрипт, що кешує
  сторінку для офлайн-роботи).
- Якщо пізніше знадобиться "справжнє" нативне відчуття (наприклад, push-сповіщення), можна додати
  обгортку (Capacitor) над тим самим React-кодом — не потрібно переписувати з нуля.
