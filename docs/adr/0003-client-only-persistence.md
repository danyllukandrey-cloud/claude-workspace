# ADR-0003: Зберігання даних тільки в браузері (без бекенду на старті)

- Статус: Accepted (прийнято за замовчуванням — переглянь і скажи, якщо треба інше)
- Дата: 2026-07-02

## Контекст

Застосунку "ПЛАН" потрібно десь зберігати введені користувачем дані (портфель, суми, майбутні
картки з інших сфер). Перша картка (калькулятор ребалансування) свідомо спрощена: ціна акції
вводиться вручну, без запиту до зовнішнього сервісу.

## Розглянуті варіанти

1. **Тільки `localStorage` в браузері**, доступ через окремий шар абстракції `src/shared/storage/`.
2. **Невеликий сервер + база даних одразу** (Node.js + PostgreSQL/SQLite).

## Рішення

Обрано варіант 1: дані живуть у `localStorage`, доступ — тільки через шар абстракції
`src/shared/storage/` (жодна картка не звертається до `localStorage` напряму).

## Обґрунтування

- Немає потреби піднімати й хостити сервер заради MVP з однією карткою — зайва складність "про
  запас".
- Шар абстракції означає, що коли бекенд таки знадобиться (синхронізація між пристроями, чи
  сервер-проксі для запиту ціни акції через зовнішній API), заміна відбувається всередині
  `src/shared/storage/`, а не в кожній картці.

## Наслідки

- Дані не синхронізуються між пристроями; очищення даних браузера = втрата збереженого стану.
- Коли з'явиться потреба в зовнішньому API цін на акції, знадобиться або дозвіл цього сервісу на
  запити прямо з браузера (CORS), або невеликий сервер-проксі — рішення приймається окремим ADR
  у момент, коли ця фіча реально розробляється.
