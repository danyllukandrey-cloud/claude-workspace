# BUGS — реєстр функціональних багів «ПЛАН», знайдених при живому тестуванні

Одне місце, куди записуємо кожен знайдений **функціональний баг застосунку** — неправильну поведінку живого продукту (розрахунок, відображення, взаємодія), а не розбіжність документів. Розбіжності документів — окремий реєстр, [`docs/ISSUES.md`](ISSUES.md), тут їх не пишемо.

Мета — не загубити знахідку під час живого тестування, навіть якщо виправляємо не одразу: спершу записуємо, потім свідомо беремось за виправлення.

## Як цим користуватись

**Це журнал знахідок, не журнал виправлень.** Знайшов баг у живому застосунку → рядок сюди одразу, навіть якщо не виправляєш зараз. Береш у роботу → статус «у роботі». Виправив через `/sdd:fix` → статус «закрито», посилання на `docs/features/<фіча>/_fixes/<date>-<slug>.md` і коміт/PR.

**Що вважається багом (пишемо сюди):**
- Застосунок рахує, показує чи поводиться інакше, ніж очікується за задокументованою поведінкою (`spec.md` фічі) або за здоровим глуздом користувача.
- Розбіжність між тим, що показують два різні екрани для того самого факту (наприклад, картка й аналітика).

**Що НЕ пишемо сюди:** нестиковки документів (`docs/ISSUES.md`), дрібні космети́чні правки без логіки — їх просто виправляють на місці.

**Формат рядка:** один баг — один рядок реєстру. Номер `BUG-NN`, наступний вільний — рахувати максимум:

```powershell
Select-String docs\BUGS.md -Pattern '^\| BUG-(\d+) \|' | ForEach-Object { [int]$_.Matches.Groups[1].Value } | Sort-Object | Select-Object -Last 1
```

## Статуси

| Статус | Значення |
|---|---|
| **відкрито** | знайдено, ще не досліджували |
| **у роботі** | досліджується чи виправляється (напр. через `/sdd:fix`) |
| **закрито** | виправлено — див. колонку «Виправлення» |
