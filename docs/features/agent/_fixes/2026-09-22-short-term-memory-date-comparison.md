# Fix: агент "забуває" щойно сказане в межах поточної сесії (чат)

## Symptom

Користувач у чаті продукту ПЛАН на початку розмови назвав книгу («Вибачте, я зруйнував вашу компанію», Бен Горі).
Через кілька реплік у тій самій розмові (той самий календарний день, звичайний денний/вечірній київський час — не опівнічний перехід) попросив «додати прочитану книгу».
Агент перепитав «Яку книгу ти прочитав?», ніби не бачив початку розмови.
Очікувалось (AC-15): агент не забуває щойно сказане до кінця сесії.
Отримано: агент не бачив жодного попереднього повідомлення сесії взагалі.
Це перший день, коли чат тестувався проти реального Claude API (не заглушки) — тому баг ніколи раніше не спостерігався наживо.
Зачіпає всіх користувачів, будь-якої пори доби, від самого впровадження AC-15.

## Root cause

`chat_message.session_date` — колонка типу Postgres `DATE`.
Драйвер `pg` (`server/db.ts`) не має налаштованого `pg.types.setTypeParser` для OID 1082, тому за замовчуванням повертає значення як об'єкт JS `Date`, а не рядок.
`toChatMessageRecord` (`src/agent/infra/postgres-repo.ts:455-464`, до фіксу) передавала `row.session_date` без перетворення, хоча інтерфейс `RawChatMessageRow` (рядок 451) хибно оголошував це поле як `string`.
У домені `getShortTermWindow` (`src/agent/domain/memory.ts:58`) фільтрує `message.sessionDate === sessionDate` — порівняння `Date === рядок` в JavaScript завжди `false`, тож коротке вікно пам'яті сесії (AC-15) у проді завжди було порожнім, незалежно від часу доби.
SQL-запит (`listMessagesForSession`, `postgres-repo.ts:484-489`) сам по собі коректний — рядки читались, але губились саме на межі інфра→домен.
Це не спіймали раніше, бо всі існуючі unit-тести (`rawChatMessageRow()` у `postgres-repo.test.ts:82-92`) заглушували `session_date` одразу рядком — реальної поведінки `pg`-драйвера (повернення `Date`) вони не відтворювали.

## The pinning test

`postgres-repo.test.ts` → `insertChatMessage + listMessagesForSession -- AC-15 same-session short-term window` → `normalizes a session_date returned as a real Date object (actual node-pg driver behaviour) to a plain YYYY-MM-DD string` (unit-рівень, мокований `Db`).

Провал до фіксу:
```
AssertionError: expected 2026-01-01T00:00:00.000Z to be '2026-01-01' // Object.is equality
```

## Spec patch

Нічого не змінено — AC-15 (`docs/features/agent/spec.md:207-210`) уже точно описує очікувану поведінку («агент не «забуває» щойно сказане до кінця сесії»).
Формулювання перевірено повторно й лишається чинним без правок.

## Follow-ups

- **Окрема, споріднена проблема (AC-09, довгострокова пам'ять між сесіями):** параметр `topic` ніколи не передається з реального REST-роуту (`src/agent/ports/chat-handler.ts:267-272` викликає `handleMessage` без `topic`; `MessageCreateBody`/`openapi.yaml` не мають цього поля) — `longTermFacts` у проді завжди порожній. Це інша причина, ніж цей фікс, і потребує окремого `/sdd:fix`.
- Підтвердження пропозиції не пише `chat_message` (`ui/ChatPanel.tsx:36`) — цей крок діалогу лишається невидимим для наступного ходу навіть після цього фіксу. Потребує окремого розгляду.
- Вартий розгляду: інтеграційний тест проти реального Postgres для `chat_message` — цей клас помилок (розбіжність задекларованого TS-типу й рантайм-типу з `pg`-драйвера) unit-тести з мокованим `Db` принципово не ловлять.
