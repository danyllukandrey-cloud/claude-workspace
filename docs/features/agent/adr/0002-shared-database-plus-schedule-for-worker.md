# 0002 — Worker integrates with backend-service via the shared database and its own schedule

- **Status:** Accepted
- **Date:** 2026-08-25
- **Deciders:** Андрій + Клод під час `/sdd:design agent`

## Context

ADR-0001 виділив `worker` в окремий C4-контейнер для звітів активності (AC-11: тижневий/місячний/квартальний, D-70). Потрібно вирішити, як `worker` дізнається, що настав час формувати черговий звіт, і звідки бере дані про активність користувача за період.

## Decision drivers

- Availability 99.0% (spec §6) — worker не повинен вводити нову точку відмови для синхронного шляху чату.
- Одна людина веде розробку (~1–2 год/тиждень) — операційна складність (черги, окрема інфраструктура) має ціну.
- AC-11 вимагає лише пасивний запис, без сповіщень — немає вимоги «доставити подію негайно», тож немає технічної причини для event-driven складності.

## Considered options

1. **Спільна база + власний розклад (cron)** — `worker` читає ту саму PostgreSQL-базу, що й `backend-service`, і сам вирішує, коли час писати черговий звіт.
2. **Окрема черга/подія від backend-service** — `backend-service` явно емітить подію «час звіту», `worker` лише споживає чергу.

## Decision outcome

**Chosen:** Option 1. Немає реальної потреби в event-driven розв'язці — тригер часовий (тиждень/місяць/квартал), не подієвий; `worker` сам обчислює «чий звіт зараз», читаючи активність напряму з бази. Це найпростіша інтеграція, яку може підтримувати одна людина, і не вводить нову інфраструктуру (чергу) заради нічим не обґрунтованої гнучкості.

## Consequences

**Positive**
- Жодної нової інфраструктури (черга/брокер) — менше операційного навантаження.
- `worker` і `backend-service` діляться однією схемою — не потрібно синхронізувати дві копії даних активності.

**Negative**
- Схема таблиць і міграції спільні для обох контейнерів — зміна структури зачіпає й `worker`, і `backend-service` одночасно (multi-module impact, тому і ADR).
- `worker` має власну логіку обчислення «за який період і кому зараз звіт», яку не бачить `backend-service` — обидва мусять узгоджено читати одні й ті самі поля.

**Neutral**
- На старті `worker` і `backend-service` можуть тимчасово ділити один процес/деплой (наприклад `node-cron` у тому самому Node-процесі) — контейнерна межа лишається логічною; фізичне розділення на окремий деплой-юніт відкладається до реального навантаження (ADR-0001, Neutral).
