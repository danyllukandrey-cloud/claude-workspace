# 0005 — Layer the backend as domain/app/infra/ports

- **Status:** Accepted
- **Date:** 2026-08-25
- **Deciders:** Андрій + Клод під час `/sdd:design agent`

## Context

`agent` — перша фіча, чий код реально живе на бекенді («мінімальний бекенд», D-24); бекенд ще жодного разу не піднімався (DELIVERY-PLAN «Розробка» 5%). Рішення про шарову структуру тут неминуче стає конвенцією для будь-якої майбутньої backend-фічі (синхронізація, OAuth конекторів, тощо) — не лише для `agent`.

## Decision drivers

- Фронтенд продукту вже має усталену філософію — домен окремо від UI (`domain/` + `ui/`, [ADR-0004 scaffold architecture](../../adr/0004-scaffold-architecture.md)); та сама лінія на бекенді знижує когнітивне навантаження на єдиного розробника.
- ADR-0004 (agent, примус правил) і майбутній `data-model agent` потребують чіткого місця для доменної логіки (правила, стан пропозиції), окремого від HTTP-шару й від інфраструктурних викликів (Postgres, Claude API).
- Одна людина в темпі ~1-2 год/тиждень (spec §2 SAD Constraints) — зайвий boilerplate коштує реального часу.

## Considered options

1. **domain/app/infra/ports** — доменна логіка (правила, стан пропозиції, розрахунки) без зовнішніх залежностей; app — use-case оркестрація; infra — реалізації (Postgres-репозиторій, Claude API клієнт); ports — HTTP-хендлери/DTO.
2. **Простий шар routes+services** — один шар маршрутів/хендлерів, один шар сервісів із бізнес-логікою, без окремих domain/infra/ports тек.

## Decision outcome

**Chosen:** Option 1. Продукт уже говорить мовою «домен окремо від доставки» на фронтенді (ADR-0004 scaffold) — та сама лінія на бекенді дає одну ментальну модель на весь проєкт, а не дві різні філософії в одному репозиторії. Домен без зовнішніх залежностей (Claude API, Postgres) також критичний для ADR-0004 (agent): guard-перевірка правила має бути тестованою окремо від реального виклику LLM.

## Consequences

**Positive**
- Доменна логіка (правила, розрахунок стану пропозиції, guard-перевірка) тестується без мережі й без бази — швидкі unit-тести.
- Заміна Claude API на іншого постачальника чи PostgreSQL на іншу СУБД зачіпає лише `infra/`, не `domain/`.
- Одна конвенція на весь продукт (фронт + бекенд) — новий контриб'ютор (чи майбутня фіча) не вгадує стиль наново.

**Negative**
- Більше топ-рівневих тек на файл такого розміру, ніж дав би найпростіший варіант — накладні витрати відчутні на дуже маленьких PR.
- Потребує дисципліни: спокуса «швидко долити виклик Postgres прямо в app-шар» завжди є.

**Neutral**
- Точний склад `ports/` (REST/OpenAPI-контракт) — предмет `/sdd:api agent`, не цього ADR.
