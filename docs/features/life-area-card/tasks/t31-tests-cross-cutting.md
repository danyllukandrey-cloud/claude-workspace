# T31 — Tests: cross-cutting integration

## Why

QG-1 (офлайн) і AC-04 (ізоляція) — [`sad.md §10`](../sad.md#10-quality-requirements), обидва наскрізні перевірки, що охоплюють кілька шарів разом.

## What

E2e: користувач A ніколи не бачить карток/записів користувача B, жодним ендпоінтом (AC-04). Окремо: запис офлайн (T11) → підключення → підтвердження, без втрати даних і без розсинхронізації з бекендовим розрахунком прогресу (ADR-0001).

## Definition of Done

- [ ] E2e test: користувач A створює картку/запис → користувач B жодним запитом їх не бачить
- [ ] E2e test: офлайн-запис синхронізується й підтверджується після підключення, прогрес на клієнті й бекенді збігається
- [ ] lint + vet clean

## Notes

Остання задача перед `/sdd:plan-tests life-area-card` — тут зводяться докупи наскрізні гарантії, які жоден окремий шар не перевіряє сам.
