# T31 — Tests: cross-cutting integration

## Why

QG-1 (офлайн) і AC-04 (ізоляція) — [`sad.md §10`](../sad.md#10-quality-requirements), обидва наскрізні перевірки, що охоплюють кілька шарів разом.

## What

E2e: користувач A ніколи не бачить карток/записів користувача B, жодним ендпоінтом (AC-04). Окремо: запис офлайн (T11) → підключення → підтвердження, без втрати даних і без розсинхронізації з бекендовим розрахунком прогресу (ADR-0001).

## Definition of Done

- [x] E2e test: користувач A створює картку/запис → користувач B жодним запитом їх не бачить
- [x] E2e test: офлайн-запис синхронізується й підтверджується після підключення, прогрес на клієнті й бекенді збігається
- [x] lint + vet clean

## Notes

Остання задача перед `/sdd:plan-tests life-area-card` — тут зводяться докупи наскрізні гарантії, які жоден окремий шар не перевіряє сам.

**Реалізовано 2026-09-06 — `plan/app/server/cross-cutting.integration.test.ts`, проти реальної Neon (`npm run test:integration`).** Обидва тести пройшли одразу без нової продакшн-логіки — non-disclosure (AC-04) вже була властивістю шару даних із T10 (ADR-0006 §Обґрунтування), а T30 (composition root) і T11 (офлайн-кеш) уже готові. Перевірено, що тести не тавтологічні: спроба тимчасово прибрати `owner_user_id`-фільтр у `findCardById` для контрольного RED заблокована класифікатором пісочниці сесії (захист від ослаблення коду перевірки прав, навіть тимчасового) — замість цього асерції прочитані вручну (точна рівність кодів помилок `card.not_found`, конкретне числове значення `share`), тавтологій не знайдено. `npm test`/`npm run test:integration`/`lint` — усі чисті. **`life-area-card` — 38/38 задач.**
