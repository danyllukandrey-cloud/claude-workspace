## Частина 1 — БД + домен + інфра (T3-T10, T27)

### Stage 1 — відповідність AC/DoD

- **[critical]** Нормалізація рангу в `aggregate.ts:50-55` (AC-06) рахує `maxIndex = cards.length - 1` замість нормалізації по сітці — при розріджених `cellIndex` (є картки без прогресу) ранг вилітає за 0..1 і стає від'ємним. Тест зелений лише тому, що клітинки в ньому йдуть підряд.
- **[major]** Семантика тренду (AC-07) суперечлива: код порівнює знакове значення gap, коментар тесту каже "за модулем", тест на "shrinking" фактично подає зростання модуля.
- **[major]** `cellIndex: null` («картка без клітинки») неможливо зберегти — колонка в БД `NOT NULL`, app-шар пише замість null реальний `baseOrder`. AC-11b/AC-16b/AC-17 не спостережувані.
- **[major]** AC-09 без робочого шляху: `defaultPositionForNewCard`/`insertLayoutPosition` існують, але жоден рядок коду їх не викликає — нова картка не отримує клітинку.
- **[major]** `logic_variant` не обнуляється при виході з режиму `logic` — інваріант AC-16 не тримає ніхто (доменна перевірка мертва, продубльована інлайном в app-шарі без цього випадку).
- **[major]** T9 DoD вимагає інтеграційного тесту на реальній БД — є лише mock із тавтологічними assert'ами (завжди `rows: []` → завжди `null`).
- **[major]** T8 DoD "survives offline" не виконаний — `history.ts` чистий append у масив, 0 викликачів у всьому `src/`.
- **[minor]** "reverts cleanly" (T3/T27 DoD) перевірено лише для up-боку міграцій, не down.

### Stage 2 — якість

- **[major]** LWW (останній запис переможе) не захищений у SQL — `WHERE` не перевіряє `position_updated_at`, рішення конфлікту лише read-then-write в app-шарі.
- **[major]** Інфра обходиться сирим SQL в app-шарі (`close-card.ts`, `update-structure.ts`) — пише напряму в `structure_layout_position`, мимо репозиторію T9, без scoping і без транзакції в reset-циклі.
- **[minor]** Немає мапінгу Postgres-помилки 23505 (унікальний індекс) на контрактну колізію 409.
- **[minor]** `findHistoryEventsAsOf` не scoped по власнику (на відміну від решти репозиторію).
- **[minor]** `detail` для події `moved` не пишеться (`null`), хоча `get-analytics.ts` його парсить — тренд (AC-07) не розрахується на реальних даних.
- **[minor]** `declaration.ts` кидає звичайний `Error` (не типізовану помилку домену), і правило валідації мертве — PATCH не перевіряє.
- **[nit]** Два написання "структури" й enum'а в домені/інфрі; параметри режиму в двох функціях домену проігноровані (`_layoutMode`, `_newMode`).

## Частина 2 — App + Ports (T11-T18)

Підтверджено з Частини 1: rank-нормалізація тече в `get-analytics`, `history.ts` не викликається ні з `move-card.ts`, ні з `close-card.ts`, `detail: null` у `moved`, `logic_variant` не скидається, сирий SQL мимо репозиторію й без транзакції.

### Stage 1

- **[critical]** AC-11b/AC-16b: reset пише реальні клітинки 0..N-1 замість "без клітинки" — домен віддає `cellIndex: null`, але `update-structure.ts:91-98` пише `position.baseOrder` замість NULL. Корінь — `cell_index INTEGER NOT NULL` у міграції 02.
- **[critical]** AC-07 і `/layout/history` не працюють на реальних даних: `move-card.ts` пише `moved`-подію без `detail`, а обидва читачі (`get-analytics.ts`, `layout-handlers.ts`) вимагають рядок `cell_index -> N`. Тренд завжди `null`, history завжди `[]`. Тести самі підкладають `detail` рукою — зелені попри зламану фічу.
- **[major]** T11 DoD "в одній транзакції" не виконано — UPDATE структури + N окремих UPDATE позицій без жодної транзакції.
- **[major]** **Жоден ендпоінт Структури не зареєстрований на сервері** (`server/app.ts`) — лише `/session` і `/cards*`. Контрактні коди відповіді ніде не спостережувані в реальному застосунку; 401 із DoD T15/T16 не підключений.
- **[major]** AC-16: `logic_variant` не скидається при виході з `logic` (підтверджено з іншого боку) + похідний дефект: подальший PATCH `{logicVariant: null}` на вже-`free` структурі дає 500 замість 422 (помилка домену нікуди не мапиться).
- **[major]** AC-12: закриття напрямку відбувається ДО переносу метрик і без відкату — якщо перенос падає, напрямок уже закритий і подія вже в Літописі.
- **[major]** T18: колізія назви метрик (409 `metric_block.name_collision`) протікає повз контракт, який знає лише 200/401/404/422.
- **[major]** AC-07: поточний і минулий gap рахуються в різних шкалах рангу (різні набори карток) — `growing`/`shrinking` стає довільним, щойно є хоч одна картка без відсотка.
- **[major]** AC-15 (rename) не реалізована ніде — `'renamed'` існує лише як тип, 0 продуктивних викликів.
- **[minor]** `getAnalytics` (T14) — мертвий код, ніхто з production не викликає; контракт не має ендпоінта аналітики.

### Stage 2

- **[major]** Сирий SQL в обхід owner-scoped репозиторію (підтверджено) — зараз врятовано лише тим, що id прийшли з owner-scoped SELECT.
- **[major]** AC-02 у конкурентному випадку дає 500 замість 409 — унікальний індекс ловиться як сира pg-помилка, не контрактна `cell_occupied`.
- **[minor]** Подвійний запит + "вигадані" поля у відповіді close (DTO з `new Date()` замість значення з БД).
- **[minor]** `getLayoutHistoryAsOf` ігнорує закриття, сортування й пагінацію (DoD вимагає cursor-paginated).
- **[minor]** N+1 послідовних await в `get-analytics.ts` під NFR 300ms.
- **[minor]** reset ставить серверний `now()` у поле LWW замість клієнтської мітки (ADR-0002) — офлайн-черга з пізнішим клієнтським годинником перекриє скидання.
- **[minor]** Тести не пінять заявлений DoD (перевіряють "параметр передано", не цільове значення) у кількох файлах — `update-structure.test.ts`, `move-card.test.ts`, `get-analytics.integration.test.ts` (лічить блоки-метрики, не записи), `cross-cutting.test.ts` (офлайн-черга не викликається жодним app-кодом).
- **[nit]** Дублікат `parsePastCellIndex` у двох шарах; lazy-provisioning без обробки гонки (два перші GET одночасно → 500).

### Stage 1

- AC-06/AC-06b/AC-07 на реальному екрані мертві — `main.tsx` постачає `gap: null, trend: null, unmaintained: false, trendAvailable: false` завжди. Банер "тренд недоступний" висить для всіх користувачів завжди.
- AC-12 недосяжний: SCR-04 (`CloseCardDialog`) написаний і протестований, але не експортований з `index.ts` і не підключений ніде в застосунку — 0 використань поза власним тестом.
- T25 не відтворює офлайн — "офлайн-сценарій" це два послідовні виклики use-case в одному процесі, без втрати мережі/черги/реконнекту.
- SCR-03 `empty`-стан не відповідає `screens.md` і не покриває випадок "картки є, відсотка ні" (AC-13) — показує список назв без банера й без "Середній прогрес".
- Офлайн-запис оголошений, але не реалізований; SCR-01 і SCR-02 показують протилежні повідомлення на той самий мережевий збій (одне каже "збережено локально", інше — "не вдалося зберегти").
- Читання офлайн і 401 = вічний спінер на всіх трьох нових екранах (жодного `.catch`, на відміну від решти застосунку).

### Stage 2

- Тест стану `saved` тавтологічний — матчить кнопку "Зберегти", не банер "Збережено" (стан фактично не перевірений).
- Читається лише перша сторінка `GET /structure/layout` (дефолтний ліміт 50) — `collectAllPages` вже є в тому ж файлі, але не застосований тут.
- Трей нерозкладених карток без підпису — незрозуміло, чому картка там опинилась; AC-17 не згадує жодна задача в `tasks.json`.
- Доступність: `Banner` без `role="alert"/"status"`, drag&drop без клавіатурної альтернативи, `CloseCardDialog` без `role="dialog"`/фокус-пастки й не показує назву картки, що закривається.
- `CloseCardDialog`: один булін `needsRename` на весь діалог — з двома перенесеними метриками незрозуміло, яку перейменовувати.
- `rows` у `CloseCardDialog` ініціалізується раз — зміна `metricBlocks` без ремаунта кидає TypeError.
- Кілька тестів очікують `findByText(/./)`(будь-який текст) — пройдуть попри майбутню регресію.
- Подвійний клік "Зберегти" в SCR-01 відправляє два PATCH (немає `submitting`/`disabled`).
- `excludedCount` рендериться навіть при 0; розрив (gap) показується сирим числом, не у форматі, узгодженому з прогресом.
- 8 компонентів зі `screens.md §New components` не написані й не зареєстровані в інвентарі дизайн-системи.
- N+1 запитів при відкритті аналітики (по картці окремий `GET /cards/{id}`), без кешу й без батчу.
- [передано в Частину 1] Заборона "клітинка зайнята" не дивиться на режим розкладки — спрацює і в режимі "Вільно", де обмеження не мало б діяти.

## Зведений список "без цього фіча не працює" (MUST-FIX)

7. Скидати `logic_variant` при виході з режиму `logic`.
