# 0001 — Recompute Structure's aggregate progress client-side from cached card events

- **Status:** Accepted
- **Date:** 2026-08-24
- **Deciders:** Андрій Данилюк (з Клодом під час Socratic-проходу `design`)

## Context

Екран зведеної аналітики Структури показує середній прогрес усіх карток користувача (spec.md AC-01, AC-04, AC-13). spec.md §6 NFR вимагає 100% офлайн-доступність читання цього екрана. AC-05 вимагає, щоб цифра Структури ніколи не розходилась з тим, що сама картка показує. `life-area-card` уже вирішив (ADR-0001 тієї фічі), що прогрес однієї картки завжди рахується наживо з сирих подій спільним кодом клієнт+бекенд, ніколи не кешується як готовий відсоток.

## Decision drivers

- Офлайн-доступність читання — 100%, без винятків (spec.md §6 NFR).
- AC-05 (cross-context): аналітика Структури має показувати те саме число, що й сама картка, завжди — не окрему, потенційно розбіжну реалізацію.
- Уже наявний прецедент `life-area-card` ADR-0001 — «одне джерело правди, перерахунок з сирих подій, спільний код клієнт+бекенд» — Структура додає ще один рівень зведення (середнє по картках), не змінює сам принцип.

## Considered options

1. **Клієнтський перерахунок з кешу** — PWA імпортує той самий `domain/progress.ts`, що й `life-area-card`, рахує відсоток кожної картки локально над кешованими сирими подіями і сама зводить середнє — без мережевого запиту.
2. **Окремий агрегатний endpoint на бекенді** — бекенд рахує середнє по всіх картках користувача і повертає одне число; клієнт лише показує.

## Decision outcome

**Chosen:** Option 1. Вимога spec.md «100% офлайн-читання» технічно виключає варіант 2 без додаткового кешування самого агрегованого числа — а це відтворило б саме ту проблему («друге джерело правди»), яку `life-area-card` ADR-0001 уже вирішив на рівні однієї картки. Клієнтський перерахунок зводить обидва рівні (картка → Структура) до одного й того ж принципу.

## Consequences

**Positive**
- Офлайн-читання аналітики працює за визначенням — немає мережевого запиту, який міг би впасти.
- AC-05 виконується конструктивно: Структура й картка буквально викликають ту саму функцію над тими самими даними — розійтися їм нема як.

**Negative**
- Перерахунок на льоту для N карток при кожному відкритті екрана аналітики — вартість O(N) сумарних подій. При MVP-обсягах (десятки карток) не проблема; за потреби оптимізації — кешування з інвалідацією пізніше (борг, sad.md §11).

**Neutral**
- Якщо колись з'явиться сервер-рендер поверхня без браузера (наприклад email-звіт), той самий `domain/progress.ts` можна викликати і на бекенді — код спільний, просто інша точка виклику.
