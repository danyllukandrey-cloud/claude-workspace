### SCR-01 — Декларація

> **Оновлено (вимоги 14/15, Андрій, чат).** Дворівневий вибір (3 варіанти групування, а всередині «За логікою» — ще 3 підвиди) замінено на ОДИН плоский список 5 пігулок. «Одна картка» скасована повністю (навіщо режим «одна картка», якщо картку й так можна створити рівно одну) — `LogicVariantPicker` як окремий умовний компонент більше не існує, три колишні підвиди «за логікою» (D-83) стали трьома з п'яти рівноправних пунктів списку. Новий п'ятий пункт — «Готово до розкладання» (`staging`): картки з'являються внизу екрана без клітинки, користувач розкладає сам (SCR-02).
>
> **Оновлено ще раз (живе тестування, Андрій).** `LayoutModePicker` і `ConfirmDialog` (колишні AC-11/AC-11b на цьому екрані) переїхали ЦІЛКОМ на SCR-02 — «Налаштування розкладки схеми переносимо в сторінку схеми». Цей екран сам більше не знає про `layoutMode` взагалі, лише про текст декларації. Замість однієї форми (textarea + пікер + «Зберегти») — два під-стани: VIEW (текст read-only) і EDIT (той самий textarea, що й раніше), перемикач між ними — одна плаваюча кнопка «Змінити декларацію» знизу по центру, поверх контенту.

### SCR-02 — Схема

> **Оновлено D-131-наступним рішенням (Андрій, чат, 2026-09-15).** "Схема не працює і вона жахлива. Пропоную прибрати повністю оті клітинки." Фіксована сітка клітинок (`LayoutGrid`) прибрана ПОВНІСТЮ. Екран тепер — ОДНА канва (`NEW: LayoutCanvas`, верхні 70% висоти екрана) з картками, вільно позиційованими у відсотках (`x`/`y` 0-100), + купка нерозкладених карток знизу (решта висоти, звичайний потік, не окрема "зона базового розташування"). Драг — реальний Pointer Events API (миша й дотик), не HTML5 `draggable`. Новий інструмент "Зв'язати" (`NEW: ConnectionTool`) створює лінії/стрілки між картками; SVG-шар малює їх поверх канви, перераховуючи координати живо під час драгу.
>
> `LayoutModePicker`/`ConfirmDialog` (пікер режиму розкладки, під-стан `config`) НЕ змінені цим переходом — лишаються дослівно, як після попереднього проходу (D-131, "живе тестування"). Побічна дія зміни `layoutMode` змінилась ЗМІСТОВО: сервер більше не скидає картки в трей (AC-11b reset-у-базовий-порядок прибраний) — рахує РЕАЛЬНИЙ авто-розклад нового режиму (координати x/y + за потреби зв'язки), тож board одразу показує нову розкладку, а не порожню сітку "розклади заново".

AC-02 (D-62, колізія клітинки, `409 structure.cell_occupied`) прибрана ПОВНІСТЮ D-131-наступним рішенням — вільне позиціювання дозволяє карткам перекриватись, немає стану "клітинка вже зайнята" й немає колишнього окремого `error-cell-occupied`.

```text
+--------------------------------------+
| Схема                                 |
| +------------------------------------+
| |         (канва -- верхні 70%)      |  ← картки вільно позиційовані (x/y %)
| |   [Картка A]        [Картка C]     |     лінії/стрілки між ними (SVG)
| |        \              /            |
| |         [Картка B]---               |
| +------------------------------------+
| [Картка D] [Картка E]                 |  ← купка нерозкладених (решта висоти)
|      [ Зв'язати ]  [ Конфігурація ]   |  ← плаваючі, знизу по центру
+--------------------------------------+
```

`linking` — обрано інструмент, чекає тапи по картках (вимоги 4/5):

```text
+--------------------------------------+
| Схема                                 |
|  Оберіть першу картку, потім другу   |
| +------------------------------------+
| |         (канва)                    |
| +------------------------------------+
| [Картка D] [Картка E]                 |
|   [ Лінія ] [ Стрілка ] [ Готово ]    |  ← перемикач + вихід з режиму
+--------------------------------------+
```

`staging` — той самий трей унизу, СТІЙКИЙ стан (не одноразовий банер), бо авто-розклад цього режиму НІЧОГО не пише:

```text
+--------------------------------------+
| Схема                                 |
|  Готово до розкладання — перетягни   |
|  картки знизу на канву               |
| +------------------------------------+
| |         (канва -- порожня чи       |
| |          частково заповнена)       |
| +------------------------------------+
| [Картка A][Картка B][Картка C]        |  ← купка нерозкладених
|      [ Зв'язати ]  [ Конфігурація ]   |
+--------------------------------------+
```

`config` — пікер, той самий спільний список, жодної вкладеної групи (D-111), не змінений цим переходом:

```text
+--------------------------------------+
| Схема — Конфігурація                 |
|                                       |
| Спосіб розкладки:                    |
| ( ) Баланс навколо ядра              |
| (•) Фокус і спостереження            |
| ( ) Причина і наслідок               |
| ( ) Вільна розкладка                 |
| ( ) Готово до розкладання            |
|                                       |
|              [ Зберегти ]            |  ← плаваюча, знизу по центру
+--------------------------------------+
```

```text
+--------------------------------------+
| Змінити спосіб розкладки?            |
|                                       |
| Зміна розкладки перерахує авто-      |
| розклад для всіх карток за новим     |
| режимом (нові позиції, за потреби -- |
| нові зв'язки).                       |
|                                       |
|       [ Скасувати ]  [ Змінити ]     |
+--------------------------------------+
```
