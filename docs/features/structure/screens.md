## Screens

### SCR-01 — Декларація

> **Оновлено (вимоги 14/15, Андрій, чат).** Дворівневий вибір (3 варіанти групування, а всередині «За логікою» — ще 3 підвиди) замінено на ОДИН плоский список 5 пігулок. «Одна картка» скасована повністю (навіщо режим «одна картка», якщо картку й так можна створити рівно одну) — `LogicVariantPicker` як окремий умовний компонент більше не існує, три колишні підвиди «за логікою» (D-83) стали трьома з п'яти рівноправних пунктів списку. Новий п'ятий пункт — «Готово до розкладання» (`staging`): картки з'являються внизу екрана без клітинки, користувач розкладає сам (SCR-02).
>
> **Оновлено ще раз (живе тестування, Андрій).** `LayoutModePicker` і `ConfirmDialog` (колишні AC-11/AC-11b на цьому екрані) переїхали ЦІЛКОМ на SCR-02 — «Налаштування розкладки схеми переносимо в сторінку схеми». Цей екран сам більше не знає про `layoutMode` взагалі, лише про текст декларації. Замість однієї форми (textarea + пікер + «Зберегти») — два під-стани: VIEW (текст read-only) і EDIT (той самий textarea, що й раніше), перемикач між ними — одна плаваюча кнопка «Змінити декларацію» знизу по центру, поверх контенту.

### SCR-02 — Схема

> **Оновлено (живе тестування, Андрій).** «Налаштування розкладки схеми переносимо в сторінку схеми» — `LayoutModePicker` (один плоский список 5 пігулок, вимоги 14/15) і `ConfirmDialog`-попередження про скидання (колишні AC-11/AC-11b) переїхали сюди дослівно з SCR-01. Новий під-стан `config`: плаваюча кнопка «Конфігурація» знизу по центру відкриває пікер, «Зберегти» застосовує вибір і повертає на `default`/board. `hasArrangedCards` більше не окреме поле стану — рахується напряму з уже завантажених карток (чи хоч одна має клітинку).

| State | Trigger / condition | Components (from the inventory) | Source-ref |
|---|---|---|---|
| loading | початкове `GET /structure/layout` | `NEW: Spinner` | — |
| empty | жодної картки в колоді ще немає | `NEW: EmptyState` (плаваючої кнопки «Конфігурація» тут немає — нема що розкладати) | — |
| default (board) | активні позиції завантажені, картки на клітинках | `NEW: LayoutGrid`, `CardShell`, плаваюча `Button` «Конфігурація» знизу по центру | wireframe нижче |
| reset-basic-order | щойно змінено `layoutMode` (на будь-яке з 5 значень, вимоги 14/15) — картки внизу екрана в базовому порядку (AC-11b) | `NEW: LayoutGrid`, `CardShell`, `NEW: Banner` («розклади картки заново») | wireframe нижче |
| staging | `layoutMode = 'staging'` («Готово до розкладання», вимога 15) і лишається хоч одна нерозкладена картка — той самий трей унизу, але СТІЙКИЙ стан, не одноразовий банер | `NEW: LayoutGrid`, `CardShell`, `NEW: Banner` («готово до розкладання — перетягни картки знизу») | wireframe нижче |
| error-cell-occupied | перетягнуто на зайняту клітинку в розкладці з фіксованою сіткою (AC-02, `409 structure.cell_occupied`) | `NEW: Banner` (inline поруч із клітинкою) | — |
| error | мережева помилка при збереженні позиції | `NEW: Banner` | — |
| config | клік «Конфігурація» на board | `NEW: LayoutModePicker` (той самий плоский список 5 пігулок, дослівно з колишнього SCR-01), плаваюча `Button` «Зберегти» знизу по центру | wireframe нижче |
| config-confirm-reset | у `config`, обрано ІНШЕ значення `layoutMode`, а картки вже розкладені (AC-11/AC-11b) | `NEW: ConfirmDialog` | wireframe нижче |
| config-error | `PATCH /structure` (лише `layoutMode`) повернув помилку — екран лишається в `config` | `NEW: Banner` (inline, ніколи `alert`) | — |

```text
+--------------------------------------+
| Схема                                 |
|  [Картка A] [Картка B] [  порожньо  ]|
|  [  порожньо ] [Картка C] [Картка D] |
|  [Картка E] [  порожньо ] [ порожньо]|
|                                       |
|           [ Конфігурація ]           |  ← плаваюча, знизу по центру
+--------------------------------------+
```

```text
+--------------------------------------+
| Схема                                 |
|  Розклади картки заново під нову схему|
|  [Картка A][Картка B][Картка C][Картка D][Картка E]  ← внизу, базовий порядок
|  (порожня сітка клітинок вище — чекає перетягування) |
|           [ Конфігурація ]           |
+--------------------------------------+
```

`staging` виглядає ідентично (той самий трей унизу, та сама порожня сітка вище) — різниця лише в тексті банера й у тому, що він НЕ зникає після першого перегляду, поки лишається хоч одна картка без клітинки (на відміну від одноразового `justReset`):

```text
+--------------------------------------+
| Схема                                 |
|  Готово до розкладання — перетягни   |
|  картки знизу на вільні клітинки     |
|  [Картка A][Картка B][Картка C]       ← внизу, базовий порядок
|  (порожня сітка клітинок вище — чекає перетягування) |
|           [ Конфігурація ]           |
+--------------------------------------+
```

`config` — пікер, перенесений дослівно з колишнього SCR-01 (той самий спільний список, жодної вкладеної групи — D-111):

```text
+--------------------------------------+
| Схема — Конфігурація                 |
|                                       |
| Спосіб розкладки:                    |
| ( ) Баланс навколо ядра              |
| (•) Фокус і спостереження            |
| ( ) Причина і наслідок               |
| ( ) Вільна розкладка                 |
| ( ) Готово до розкладання            |
|                                       |
|              [ Зберегти ]            |  ← плаваюча, знизу по центру
+--------------------------------------+
```

```text
+--------------------------------------+
| Змінити спосіб розкладки?            |
|                                       |
| Картки вже розкладені за іншим       |
| способом. Вони скинуться вниз екрана |
| в базовому порядку — розкладете      |
| заново перетягуванням.               |
|                                       |
|       [ Скасувати ]  [ Змінити ]     |
+--------------------------------------+
```

## New components

| Component | Why no existing primitive fits | Registered in design-system |
|---|---|---|
| `TextArea` | Багаторядкове поле вводу — `TextField`/`NumberField` в інвентарі однорядкові | pending |
| `LayoutModePicker` | Вибір одного з 3 фіксованих варіантів (сегментований перемикач) — жодного picker-примітиву нема | pending |
| `CardPicker` | Вибір цільової картки з динамічного списку активних карток — інша природа даних, ніж `LayoutModePicker` | pending |
| `Spinner` | Індикатор завантаження — `design-system.md` фіксує спінер (не skeleton) як конвенцію, компонента ще не існує | pending |
| `Banner` | Інлайн-повідомлення (успіх/помилка/офлайн) — `design-system.md`: «помилки інлайн, ніколи `alert`/`confirm`», потрібен носій для цього правила | pending |
| `ConfirmDialog` | Підтвердження дії з наслідками, що не скасовуються одним кліком (AC-11b) | pending |
| `LayoutGrid` | Сітка клітинок розкладки з drag-and-drop — специфічно для Структури | pending |
| `ProgressBar` | Візуалізація відсотка прогресу картки | pending |
| `GapList` | Список розриву з двома режимами показу (ранг / прапорець) залежно від типу розкладки | pending |
| `Toggle` | Перемикач «перенести/не переносити» на метрику | pending |
| `EmptyState` | Стандартний порожній стан (текст + наступна дія) — `design-system.md` конвенція, компонента ще нема | pending |

Усі — `pending`: жоден код компонента ще не написаний ([`design-system.md`](../../design-system.md) — інвентар лише запланований). `implement` реєструє кожен назад в інвентар, коли пише реальний код.
