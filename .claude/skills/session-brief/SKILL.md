# Session Brief — короткий статус на старті сесії

## Навіщо

Щоб за 10 секунд побачити, де проєкт зараз, перш ніж почати роботу — не гортаючи
вручну DELIVERY-PLAN.md і DECISIONS.md.

## Обмеження (важливо)

Цей skill **тільки читає**. Жодного Write/Edit, жодних припущень замість реальних
даних. Якщо `docs/DELIVERY-PLAN.md` або `docs/DECISIONS.md` відсутні — сказати
прямо, що файл не знайдено, а не вигадувати статус.

## Кроки

1. Прочитати `docs/DELIVERY-PLAN.md` → таблицю «SDLC Status Overview» (фаза/%/статус).
2. З того ж файлу зібрати всі пункти під «Що в роботі 🔄» по кожній фазі →
   список «Активні роботи».
3. Прочитати `docs/DECISIONS.md` → секцію «Критичні блокери».
4. Прочитати `docs/DECISIONS.md` → порахувати рядки в секції «Відкриті питання»
   (лише кількість — деталі там-таки, не дублювати текст).
5. Необов'язково: `git log -5 --oneline` — нагадати, що робилось останнього разу.

## Формат виводу

```
📊 ПОТОЧНИЙ СТАТУС ПЛАН

Фази (docs/DELIVERY-PLAN.md):
  📋 Планування: NN% [статус]
  📊 Аналіз вимог: NN% [статус]
  🏗️ Проєктування: NN% [статус]
  💻 Розробка: NN% [статус]
  🧪 Тестування: NN% [статус]
  🚀 Розгортання: NN% [статус]
  🛠️ Супровід: NN% [статус]

Блокери:
  🔴 [текст] — або "немає" якщо секція порожня

Активні роботи:
  🔄 [опис одним рядком] — для кожного пункту "Що в роботі"

Відкритих питань у реєстрі: N (деталі — docs/DECISIONS.md § Відкриті питання)

─────────────────────────────────────────
Сесія готова! Введи /pm-start — дізнатись план на сьогодні.
```
